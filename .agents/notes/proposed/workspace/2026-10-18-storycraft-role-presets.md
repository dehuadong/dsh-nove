# Agent Note：故事工坊：角色化——主编编排与工作子代理

## 问题

故事工坊的预设把「编排」与「写作」合成一个 persona（责任编辑兼主笔）。这在单角色工作流里能跑，但一旦审稿、修订、规划拆成子代理，主 agent 的身份就自相矛盾：它既要在阶段之间做判断并把关，又要亲自产出正文。

技能也按形态而不是按角色组织：写作方法挂在主预设上，审稿人只有一段 persona，没有判断标准。

产品行为与验收由提案工作项拥有，不在这里。

## 提案

### 身份与职责

| 身份 | 挂在哪 | 职责 | 工具 |
| --- | --- | --- | --- |
| 主编 | 主预设 `storycraft` | 理解作者、判断阶段、守闸门、派活、落盘、汇报 | `story_*` 动作 + 子代理派生 + 只读文件 |
| 写手 | 子代理预设 | 按 brief 上下文写整章，返回正文 | 只读文件 |
| 审稿人 | 子代理预设（已存在） | 读正文与真值，返回问题清单 | 只读文件 |
| 修订者 | 子代理预设 | 按条目与模式改稿，返回新版本正文 | 只读文件 |
| 规划 | 子代理预设 | 产出卷纲/章纲文本 | 只读文件 |

没有任何工作子代理持有写工具或 `story_*` 动作；**落盘只发生在主编**。

### 技能跟随角色

- 主编：编排技能（阶段判断、派活条件、交接内容、验收、失败回退）；
- 写手：长篇/短篇/剧本的写法（场景、因果、信息释放、节奏、收尾）；
- 审稿人：评审矩阵（意图与约束、连续性、动机与语气、场景功能、信息一致性、视角、承诺与兑现）+ 证据/影响/修复方向 + 格式失败的边界；
- 修订者：按原因路由修补范围（局部文字 vs 结构），模式差异（修补/润色/重写/去 AI 味）；
- 规划：卷划分、主线与结局的关系、章纲五项与「一章一个变化」。

形态技能（长篇/短篇/剧本）保持独立文件，由对应的执行身份按作品的 `form` 选用。

### 交接契约

子代理收到的三样东西：

1. 任务一句话（带章号、目标、禁止事项）；
2. 输入摘录（父代理从 `story_brief` 取，不整库打开）；
3. 输出契约（JSON 清单或整章正文，含首尾标记）。

父代理校验：结构可解析、正文长度在合理区间、首尾完整、与旧版本确有差异；任何一项不过就拒绝落盘并回报原因。

## 备选方案

- **保持单 persona**：编排与写作混在一起，角色化失去意义。
- **子代理共享主编上下文（fork）**：失去上下文隔离，成本更高；工作子代理用 `spawn`。
- **子代理自己落盘**：已证明会绕过父代理（审稿 r6 事件）；禁止。

## 验收条件

1. 主编 persona 不再自称主笔；编排技能写清派活条件与兜底；
2. 审稿人产出每条含证据、影响、修复方向；格式失败不判正文坏；
3. 写手返回整章正文，父代理校验通过才 `story_write`；截断被拒；
4. 修订者只改点名条目，未点名段落逐字保留（父代理可校验）；
5. 规划返回文本，父代理 `story_outline`/`story_plan` 落盘；
6. 任一子代理不可用时，主编兜底路径仍能完成同一章。

## 风险

- 预设数量增加（主编 + 写手 + 审稿人 + 修订者 + 规划），配置面变大；
- 全文回传的 token 成本高于单代理；
- 兜底与派活两条路径的质量差异需要分别验收。
