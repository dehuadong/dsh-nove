# Agent Note：故事工坊：路线图（角色化、输入契约与后续阶段）

## 问题

角色化、提纲、质量层、形态、检索这些工作分别由不同提案推进，但**没有一张共同的路线图**：不知道哪些已交付、哪些在飞、下一个阶段依赖什么。缺少它，计划项会变成遗忘项。

## 提案

### 已交付

| 阶段 | 内容 | 证据 |
| --- | --- | --- |
| P1 | 真值五件 + 写前上下文（8KB 预算、裁剪顺序） | #3 |
| P1.5 | 阶段闸门（章纲→正文→审稿→修订→定稿→摘要） | #5 |
| P2 | 两阶段提交、投影重建、作品改名/删除/恢复 | #6 |
| P3 | 卷结构与最近 5 章滚动窗口 | #7 |
| P4 | 质量层：按作品字数口径、质检指标、修订模式 | #8 |
| P5 | 单预设「故事工坊」、形态数据化（章/篇/集）、面板两级、当前作品持久化、提纲阶段 | #9（切片 1–5）、#10 |
| P6 | 角色化：主编 + 规划 / 写手 / 修订者 / 审稿人（只读、只出文本） | #11（切片 1–5） |

### 进行中（本提案）

| 阶段 | 内容 | 依赖 |
| --- | --- | --- |
| R1 | **角色输入契约**：七项输入 × 五个角色；分段保护级别；轨迹 | — |
| R2 | **白名单校验**：写手/修订者自造人名、地名、数字被拒收 | R1 的白名单产出 |
| R3 | **交接裁剪**：审稿只给正文 + 涉及人物 + 最近三章；写手只给契约内的段 | R1 |
| R4 | 实跑验收：五个角色各跑通一次，记录产物与失败模式 | R1–R3 |

### 后续阶段

| 阶段 | 内容 | 触发条件 |
| --- | --- | --- |
| R5 | 检索与素材（FTS5：人物、设定、历史片段召回；轨迹记录） | R1 完成，且长篇超过 30 章 |
| R6 | 形态深化：短篇整体结构、剧本分集与分镜 | 作者开始写短篇或剧本 |
| R7 | 角色扩展：分析（拆解参考作品）、市场研究、续写、同人/仿写/番外 | R4 通过，且作者提出对应需求 |
| R8 | 封面、翻译、交互影游 | 有单独产品需求时 |

「暂缓」项必须写明触发条件，否则不进入排期（与对拍清单一致）。

### 实施顺序

1. R1 先做**写手与规划**的输入契约（这两类输入最复杂，也最容易被自造内容污染）；
2. 再补审稿与修订（它们复用同一拼装器，差异只在任务段与标准段）；
3. R2、R3 依赖 R1 的产出，紧随其后；
4. R4 是阶段闸门：不通过不进入 R5 及以后。

## 备选方案

- **先做检索（R5）**：没有输入契约时检索结果没有位置可放；否决。
- **先做角色扩展（R7）**：新角色会重复同样的输入问题；否决。
- **一次性重写所有角色的上下文**：无法逐段验收；按角色推进。

## 验收条件

1. 路线图里的「已交付」都有工作项与提交记录可查；
2. 「进行中」的每一项都有对应切片工作项；
3. 「后续」每一项都有触发条件；
4. 每次阶段推进后更新本文件，不另起新路线图。

## 风险

- 路线图变长后容易过期：以「已交付 / 进行中 / 后续」三段维护，过期项直接删；
- R1 的七项是**输入**层的抽象，若某个角色实际不需要某项（例如规划不需要文风），必须在契约里写明「不需要 + 理由」。
