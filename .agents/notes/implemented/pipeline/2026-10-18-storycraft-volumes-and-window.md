# Agent Note：故事工坊：卷结构与滚动窗口的技术设计

## 问题

现在每章都平铺在 `manifest.chapters` 里，写前上下文只带「上一章结尾」。写到几十章后：作者看不到结构，模型每章都要读越来越多的摘要；而长篇真正的结构单位是「卷」——一卷是一个有起承转合的故事段。

产品行为与验收由工作项拥有，不在这里。

## 决定

### 卷的存放

`bible/volumes.json`：

```json
{ "volumes": [ { "id": "v1", "title": "第一折：塌方", "from": 1, "to": 12, "summary": "…" } ] }
```

- `id` 由动作按顺序生成（`v1`、`v2`），也可传；标题必填。
- `summary` 可选，纯文本，1–2 段；缺失时该卷没有摘要。
- 校验：数组、`from`/`to` 为正整数且 `from ≤ to`、卷之间不重叠、章号必须已经是 `manifest.chapters` 里的章（避免给不存在的章分卷）。
- 写入走 `commitFiles`（与真值同一条提交路径），卷文件进真值目录，因此随作品一起可 diff。

### 动作

`story_volume`：输入 `{work, id?, title, from, to, summary?}`；`id` 存在则更新，否则新建（id 自动 `v<n>`）。
返回 `{volumes: [...], volume: {...}}`；失败码 `volume-invalid`、`volume-overlap`、`chapter-not-found`。

`story_volumes`：只读，返回每卷的 `chapters`（含摘要的章数）与 `hasSummary`。

### 写前上下文

`assembleBrief` 增加两段，插在 `hooks` 与 `previous` 之间：

1. `volumeSummary`：目标章所在卷的摘要；没有卷或卷无摘要 → `absent: true`。
2. `recentSummaries`：目标章之前最近 5 章的摘要（按章号升序拼接，逐章一行 `第 N 章：…`）；没有摘要的章跳过。

段顺序最终为：

```
intent → plan → characters → hooks → volumeSummary → recentSummaries → previous → style → wordPolicy
```

预算逻辑不变：从最低优先级整段裁剪；这两段的优先级高于 `previous`，因此极端情况下先裁 `wordPolicy`、`style`、`previous`。

### 工作台

- 章节列表按卷分组：卷标题一行（`第一折：塌方（1–12，有摘要）`），其下是该卷的章；未分卷的章放在最后的「未分卷」组。
- 每卷一个「编辑卷」按钮：展开标题/起止/摘要三个输入，确认后投递 `story_volume` 指令；新建卷用工具栏的「新建卷」。
- 顶部徽章显示卷数。

## 备选方案

- **把卷写进 manifest**：manifest 是进度清单，卷是内容结构，混在一起会让「删一章」变成改结构；放弃。
- **一卷一个目录、章文件挪进卷目录**：路径变动会让所有引用失效，也与既有章路径契约冲突；放弃。
- **自动按固定章数切卷**：用户明确要按故事线、由作者确认；自动化会把结构决策从作者手里拿走；放弃。
- **卷摘要单独建文件**：卷只有一条短摘要，放进 volumes.json 少一次读写；条目变多再拆。

## 验证

- 卷 CRUD：新建、更新、非法区间、重叠、章号不存在。
- 写前上下文：卷内章带卷摘要与最近 5 章；卷无摘要时标 absent；不足 5 章时按实际章数。
- 预算：超限时这两段按优先级被裁并报告。
- 工作台：按卷分组，未分卷组存在。
- 回归：六套断言与三条页面 spec。

## 后果

- 卷边界与章绑定会随写作调整：允许改 `from`/`to`，但重叠校验会挡住「把卷拉大盖住下一卷」的写法，需要作者先改下一卷。
- 最近 5 章摘要在章数不足时与「上一章结尾」重复表达：两段都保留（摘要给脉络、结尾给接续句），预算紧张时先裁 ending。
- 卷摘要由模型写，质量与章摘要同源；不做自动生成。
