# Agent Note: 故事工坊：角色技能文档的内容设计

Status: implemented

## 问题

现有角色技能太薄：审稿人的全部规则只有一段 persona，没有判断标准、证据要求与边界；写作方法只在主预设的技能里，与「主编」身份混在一起。子代理拿到一句「找问题」，产出的清单质量取决于运气。

产品行为与验收由提案工作项拥有，不在这里。

## 决定

### 每份角色技能必须有的四块

1. **判断标准**：这类问题按什么标准判断（不是评分，是可解释的准则）；
2. **证据要求**：每条结论必须指向正文里的具体句子或事实；
3. **影响说明**：对读者造成什么后果（出戏、看不懂、失去期待）；
4. **修复方向**：按原因给方向，并说明该由哪种模式修（局部修补 / 润色 / 重写）。

### 审稿人技能（首篇要补全的）

- 先确定适用标准：题材、目标读者、语气、发布场景不同，信息密度与节奏阈值不同；
- 长篇要看「最近几章的压力—升级—兑现—余波」是否成环，不看单章孤立判断；
- 伏笔以事件日志为准，引用真实伏笔 id 与章号，不凭章节久远制造紧迫感；
- 重复不等于推进：只有动作、认知、关系、地位或理解变了才算推进；
- 每条问题分「客观矛盾」与「口味偏好」，后者不得当成错；
- 按原因路由：文字层可局部修补；缺场景、因果断裂、时间线、视角、人物动机、兑现问题属于结构修订；
- **格式或解析失败产出「审稿不可用」，不等于正文有问题，更不授权重写**；
- 输出 JSON：`{items:[{problem, where, impact, severity, fix, mode}]}`，最多 8 条，按严重度降序。

### 写手技能

- 把章纲转成 2–4 个场景，每个场景有目标、阻力、转折、后果；
- 只写镜头里能发生的事；设定通过行动与证据释放；
- 一章一个变化；结尾留下一步的具体期待，不用套话；
- 输出整章正文，首尾标记 `<<<CHAPTER` / `CHAPTER>>>`，不加解释。

### 修订者技能

- 只改清单点名的位置；未点名段落逐字保留；
- 模式：`patch` 只动点名处、`polish` 顺语气与节奏、`rewrite` 重写、`deslop` 去腔调；
- 改完自检：事实与旧版一致（除被点名要改的），篇幅在模式允许的幅度内。

### 规划技能

- 卷划分按故事线，不按固定章数；每卷有起承转合与卷末推力；
- 章纲五项：视角、目标、阻力、代价、结尾变化；写不出结尾变化就说明这章可以并入别章。

### 编排技能（主编）

- 阶段顺序与闸门：讨论 → 提案 → 确认 → 立项 → 提纲 → 确认 → 章纲 → 正文 → 质检 → 审稿 → 修订 → 定稿 → 摘要；
- 派活条件：写正文派写手；审稿派审稿人；改稿派修订者；卷/章纲派规划；子代理不可用时自己写；
- 交接内容与验收：见提案的交接契约；
- 失败回退：子代理超时/输出不合契约 → 重试一次，再失败则自己写并记录。

## 备选方案

- **技能继续写一段话**：无法约束判断；否决。
- **技能写成评分卡**：会把质量变成数字，掩盖原因；改为「问题 + 证据 + 影响 + 修复方向」。
- **所有角色共用一份大技能**：上下文膨胀，角色边界消失；按角色拆。

## 验证

1. 五份技能文档都存在且各自含判断标准、证据、影响、修复方向四块（编排技能为派活契约）；
2. 审稿输出含 `where/impact/severity/fix/mode` 字段，父代理可校验；
3. 写手输出带首尾标记，父代理可据此判断截断；
4. 修订者输出与旧版逐段可对比，未被点名段落一致；
5. 规划输出可被 `story_outline`/`story_plan` 直接使用。

- 交付证据：四份角色技能已接入单一预设；skills.test 校验目录与 mode: all 挂载。

## 后果

- 文档变长会挤占上下文；技能按需加载，正文不放技能里；
- 判断标准写死会僵化；写明「题材与读者决定阈值」，保留判断空间。
