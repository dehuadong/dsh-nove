# Agent Note: 故事工坊：作品编排与章节生产动作的技术设计

Status: implemented

## 问题

创作型 Agent 需要把「写一部作品」拆成可追溯的动作：立项、章纲、正文、审稿、修订、状态结算。只有模式壳（人设、技能、脚本）与一个预设目录页时，模型能读到方法，却没有任何动作把结果落到作品目录；页面也没有可读的作品与章节。

本设计固定这套东西在 Harness 现有扩展点上的落法：动作如何在某个模式内可见而不污染其他会话、产物如何落盘并保留版本、页面如何只读地呈现作品并下发指令。产品范围与验收由工作项拥有。

约束：

- Harness 只有一个事实来源——落盘产物；动作成功必须带回产物引用。
- 工具按作用域分层：`ctx.tools.register()` 在无作用域上下文注册为全局，在预设的常驻组合里注册只对那个预设生效。
- 页面不直接写文件。写盘只由模型调动作完成，页面最多投递一条用户消息。
- 现有预设 id、技能行与随技能发布的脚本保持不变。

## 决定

### 边界

| 部分 | 职责 | 不负责 |
| --- | --- | --- |
| `dsh-storycraft/tools`（预设内一行，不带配置） | 注册长篇的七个动作；只在该预设的会话里可见 | 渲染、会话推进 |
| `dsh-storycraft`（bundle 入口） | 只读 HTTP 路由：作品、章节、审稿、状态、名册诊断 | 写盘、动作编排 |
| `dsh-storycraft/client`（浏览器半边） | 侧栏入口与编排工作台、指令投递 | 直接改文件、持有第二份数据 |
| 预设行 | 组装人设 + 技能 + 动作子集 | 产品行为定义 |

### 动作与作用域

动作模块由预设挂一行，因此在预设的常驻作用域里注册：该模式会话可见，其他会话不可见。本次只有长篇预设挂这一行。工具名统一 `story_*` 前缀，输入输出都是 JSON 对象；写盘动作无产物引用的成功不算成功，`story_status` 是只读动作、只返回汇总。

| 动作 | 输入要点 | 产物 | 失败语义 |
| --- | --- | --- | --- |
| `story_init` | 标题、可选 workId、形态、可选标签 | `manifest.json`、`outline/`、`chapters/`、`reviews/`、`state/`、`hooks.md` | 标题为空，或同 id 作品已存在时拒绝，不覆盖 |
| `story_plan` | 作品 id、章号、五位内容（视角/目标/阻力/代价/结尾变化） | `outline/<章>.plan.md` | 五项缺一即拒绝，不写文件 |
| `story_write` | 作品 id、章号、正文 | `chapters/<章>.md`（或新 revision）、manifest 字数与状态 | 正文为空、章号已存在且未声明改版时拒绝 |
| `story_review` | 作品 id、章号、问题清单（位置/问题/建议） | `reviews/<章>.r<N>.md`，轮次按章独立编号 | 正文不存在、清单为空时拒绝；绝不改正文 |
| `story_revise` | 作品 id、章号、问题条目 id（至少一个）、改后正文 | 新 revision 文件、清单条目标记为已处理 | 没有审稿清单、未给条目、条目不存在、正文与当前版本相同都拒绝 |
| `story_state` | 作品 id、章号、人物事实与伏笔变化 | `state/events.jsonl` 追加事件、重生成的 `hooks.md` | 缺作品或章、状态非法、「已用」指向未埋伏笔时拒绝，不写部分事件 |
| `story_status` | 作品 id | 只读汇总（进度、当前版本、未处理问题、未解伏笔） | 作品不存在时返回结构化错误 |

工具定义落在工具注册表支持的 JSON Schema 子集内：`type/oneOf/properties/required/additionalProperties/items/enum/const` 与注解，`required` 是属性名数组。写成参数定义方言（每个属性上 `required: true`）会让 `assertSupportedJsonSchema` 抛错，整条预设装载失败。

### 作品存储

- 路径：`<工作区>/works/<workId>/`，`workId` 由标题生成小写 slug（也可显式指定）；同 id 已存在时拒绝新建。
- `manifest.json`：`version`、`workId`、`title`、`form`、`tags`、`createdAt`、`updatedAt`、`chapters[]`（`id`、`number`、`title`、`status`、`currentRevision`、`words`、`updatedAt`）、`counters`（`reviewRounds`、`openProblems`）。`counters` 每次变更后由磁盘上的审稿文件重算；`openProblems` 按每章**最新一轮**统计。
- 章节文件：`chapters/ch-0001.md` 为首版；修订写 `ch-0001.r2.md`、`.r3.md`，旧文件不改写；`currentRevision` 指向当前版本。
- 审稿清单：`reviews/ch-0001.r<N>.md`，轮次按章独立编号；条目形如 `- [ ] Q1 :: 位置 :: 问题 :: 建议`，修订后原地改为 `[x]`。
- 状态：`state/events.jsonl` 追加带章号的事件（人物事实、伏笔 opened/used/resolved），`hooks.md` 由事件折叠后重生成；进度与工作台都从事件折叠，不维护第二份状态。
- 原子性与回滚：写文件先写同目录临时文件再 `rename`；manifest 最后写。提交失败或任一步出错时，本次新增的文件被删除、被改写的文件恢复原内容。
- 单写者：变更动作全程持有 `<works>/.<workId>.lock`（排他创建，超过 10 分钟视为遗留锁可接管）并校验 `updatedAt`；冲突返回 `work-busy`，不合并、不覆盖。

### 页面数据与指令

- 只读路由（入口行注册，前缀 `/api/dsh-storycraft`）：`/works?root=`、`/work?root=&id=`、`/chapter?root=&id=&chapter=&view=body|plan&revision=`、`/review?root=&id=&chapter=`，外加诊断用的 `/roster`、`/document`。全部只读，沿用同源 cookie + 仅本机策略，失败统一为 `{ ok:false, error:{ code, message } }`。
- `root` 由浏览器给出，宿主只放行工作区注册表认识的目录（两侧 `realpath` 归一化比较），避免把只读接口变成任意目录读取器。
- 页面用这些路由渲染列表、正文、审稿清单与状态；不订阅会话事件，不缓存成第二份事实。
- 指令下发：按钮把一条文本消息投递给当前会话（会话控制器在客户端暴露的消息投递接口，排队模式），由该会话的模型调动作。页面不判断"该写什么"，只表达意图（写下一章 / 审稿 / 按清单修订 / 结算状态）。
- 章节预览的 Markdown 在页面内渲染（标题、段落、分隔线、引用、列表、代码块），不引入外部渲染库；未知语法按纯文本段落显示。

### 兼容与迁移

- 现有预设 id 不变；技能行与三个脚本保留；长篇预设多挂一层动作行。
- 预设目录页由工作台取代：无作品时呈现模式说明，有作品时呈现编排。
- 短篇/剧本预设只保留模式与技能，不挂动作。
- 入口行依赖 `webServer`：不组合 Web 的部署里入口行不激活，页面与只读路由缺席，而预设内的动作行是独立模块、照常挂载。
- 没有当前会话、或当前会话不是长篇模式时，指令按钮点击后只说明原因、不投递，也不猜测目标会话；长篇预设装载失败时，工作台顶部显示宿主给出的失败原因。
- 人设模板不得使用未注册的 `{{…}}` 变量：prompt 注册表严格解析，未知变量会让该预设的每一轮失败而预设仍然装载。

## 备选方案

- **只靠文件约定，不注册动作**：模型用现有文件工具直接读写作品目录。放弃原因：没有产出校验、没有版本切换、没有结构化结果，审稿与修订无法区分"成功"与"看起来写了"。
- **页面直接调宿主接口写文件**：少一层模型调用、响应更快。放弃原因：写盘绕过模型与审稿动作，产物无法追溯到一次具体创作决定。
- **全局注册动作，用提示词区分形态**：实现最省事。放弃原因：所有会话的工具面都会被故事动作污染，且不同形态的输入契约不同。
- **每步一个子代理**：立项、章纲、正文、审稿各起一个子代理。放弃原因：每步都要重新装配上下文，状态传递只能靠文件，收益低于成本。
- **作品数据进数据库**：放弃原因：产物需要人可读、可 diff、可外部编辑；文件是唯一事实来源。

## 后果

- 作品随工作区走：删工作区即删作品，`git diff` 能看出每一步改动；跨工作区共享作品不在范围内。
- 动作直接用 Node 的文件 API 落盘，不经过 Harness 的文件沙箱；因此在 CI 或受限环境里，动作的写权限由宿主进程自身决定。页面读接口另受「仅本机 + 同源」约束。
- 会话在开始时锁定一代预设组合：修改预设配置只对新建会话生效，旧会话会继续使用旧组合（包括旧的错误模板）。
- 逐次动作都重写 `manifest.json`；书很大时章节列表的增长会让单次提交的写入量线性上升，尚未做分卷清单。
- 预设有三类会让整条预设不可用的写法，均已有离线守卫：动作行 schema 越出受支持子集（`tools.test.mjs`）、人设模板使用未注册变量（`presets.test.mjs`）、缺少必填的子插件配置（构成层面，靠宿主名册诊断发现）。
- `story_state` 只追加事件、不删；纠错需要追加更正事件，历史事件保留。

## 验证

- `node storycraft/tests/storage.test.mjs`：35 项，覆盖章纲缺项、空正文、重复写入不留文件、审稿不改正文（字节对比）、修订保留旧版并标记条目、伏笔「已用」必须先埋、失败后 manifest 不变、并发写拒绝、不可写根不留目录。
- `node storycraft/tests/tools.test.mjs`：29 项，覆盖七个动作注册、schema 形状、结构根约束、七个动作端到端、重复立项拒绝、修订缺条目/未变化拒绝、未知作品错误、章状态与字数落盘、版本递增。
- `node storycraft/tests/presets.test.mjs`：6 项，覆盖人设模板不含未注册变量、三条预设声明、动作行只挂长篇、三条技能行。
- 真实会话（长篇模式）：立项 → 章纲 → 第 1 章正文（3890 字）→ 审稿 6 条 → 按清单修订（新版本 r2、六条标为已处理）→ 状态结算（15 条事件、6 条未解伏笔）全部落盘，工作台读到同一批数据；磁盘上首版与修订版并存，无残留锁。
- 作用域：标准模式的会话工具列表里没有 `story_*`；长篇会话里动作可用。
- 证据与评审记录：工作项 `dehuadong/dsh-nove#1`。

- 交付证据：离线断言（storage 35 项、tools 29 项、presets 6 项）全过；在「长篇小说」会话里跑通立项→章纲→正文→审稿→修订→状态结算，产物落在 works/开国工程队/（首版与修订版并存、6 条审稿条目标记为已处理、15 条状态事件、6 条未解伏笔），工作台读到同一批数据。证据见工作项 dehuadong/dsh-nove#1。
