# Agent Note: 故事工坊：两阶段提交与作品改名删除的技术设计

Status: implemented

## 问题

现在每个写动作都是「直接写正式文件 + 失败按日志回滚」。回滚日志只在进程活着时有效：进程被杀、断电、或回滚本身失败，就会留下半成品——例如正文已写、manifest 没更新，或审稿文件写了、条目状态没写。作品也没有改名与删除，改名只能手动挪目录，删除只能 `rm`。

产品行为与验收由工作项拥有，不在这里。

## 决定

### 暂存目录

`works/<作品>/.staging/<动作>-<毫秒时间戳>/`，内部保持与正式目录相同的相对路径（`chapters/ch-0001.r3.md`、`reviews/ch-0001.r2.md`、`state/events.jsonl` 等）。

写动作分三段：

1. **准备**：取得单写者锁，读 manifest，计算本次要写的全部文件与最终内容，写到暂存目录。
2. **校验**：对暂存内容做与正式路径相同的校验（正文非空、审稿条目非空、JSON 可解析、字数可计算），并校验「暂存文件集合 = 计划写的集合」。
3. **提交**：按固定顺序把暂存文件逐个 `rename` 到正式路径（同盘，原子），最后写 `manifest.json`。写 manifest 成功即返回成功。

`manifest.json` 故意最后写：它是提交点。若进程在提交中途被杀，正式目录可能已经换了部分文件而 manifest 还是旧的——这种情况下读取方以 manifest 为准，且下一次写动作会检测到「暂存目录残留」并清理，不会把旧 manifest 当作新内容。

### 崩溃后的清理

启动或下次写动作时扫描 `works/<作品>/.staging/`：超过 24 小时的目录直接删除，并在结果里报告 `cleaned` 数量。不自动“补提交”——半成品不应被猜成完整提交。

### 投影

`state/projection.json` 是**派生**文件：提交时由 manifest 与事件日志重算，读取时若缺失、或 `manifestUpdatedAt` / 事件行数与记录不符则重建。它只用于页面快速读取，不作为真源；删掉它不会有任何损失。

### 改名

`story_rename(work, title?, workId?)`：

- 持锁，读 manifest，校验新 id（`slugify` 后非空、不与现有作品冲突、不是保留名）。
- 若 id 变化：`rename(works/<旧>, works/<新>)` → 更新 manifest 的 `workId` 与 `title` → 原子写回。目录重命名在同一盘内是原子的；此后锁文件名也随 id 变化，因此必须在持锁期间完成并释放旧锁。
- 若只改标题：只写 manifest。

改名时的锁：锁文件名由作品 id 派生（`works/.<id>.lock`），目录改名后旧锁路径失效。因此顺序固定为「取旧锁 → 改目录 → 改 manifest → 把锁文件改名为新 id → 释放新锁」；锁文件改名失败时回滚目录与 manifest，并保留旧锁到释放。

### 删除与恢复

`story_delete(work)`：持锁确认无未完成暂存 → `rename(works/<作品>, works/.trash/<作品>-<时间戳>)`。列表扫描跳过 `.trash` 与 `.staging`。`story_restore(name)`：在 `.trash` 里按「目录名以 `<作品>-` 开头」找最新一份，改名回 `works/<作品>`；目标已存在则拒绝。

## 备选方案

- **用 SQLite 事务替代暂存目录**：真源会变成数据库，作品不再可读可 diff；与既有契约冲突。放弃（索引仍可用 SQLite，见 #4 H 组）。
- **写前备份整个作品目录**：简单但每次复制整本书，250 章时不可接受。
- **只靠回滚日志**：现状，进程被杀就失效；不解决核心问题。
- **删除即真删**：省事但不可恢复；回收站成本很低。
- **改名只改标题不改 id**：回避目录重命名，但用户无法修正自己起的 id；改名仍需原子性，成本差不多。

## 验证

- 正常提交：无残留暂存，manifest 是最后写。
- 可测性：提交过程暴露一个只在测试里用的失败注入点（在「暂存完成、提交前」抛错），用于验证正式目录不变。
- 故障注入：暂存写完、提交前杀进程 → 正式目录与 manifest 不变，重试成功。
- 校验失败：拒绝且正式目录不变。
- 并发：一个成功一个 `work-busy`。
- 投影：删除后重建一致。
- 改名：目录/manifest/锁名一致，旧目录不存在，重名拒绝。
- 删除/恢复：列表、回收站、内容完整。
- 回归：五套断言与三条页面 spec。

- 交付证据：六套离线断言全过（新增 work-ops 32 项：改名/删除/恢复、投影重建、暂存不落盘/提交落盘/丢弃、故障注入、越界路径与空产物拒绝）；三条页面 spec 全过；真实会话验收：标题改名、删除到回收站、从回收站恢复均通过。证据见工作项 dehuadong/dsh-nove#6。

## 后果

- 写入路径变长（多一次暂存校验），换来崩溃安全；单章写入的额外成本在毫秒级。
- `.staging` 与 `.trash` 必须被工作台与列表忽略，也要进 `.gitignore` 的考虑范围（作品目录在版本库里时）。
- 改名改变 id 会让旧会话里缓存的 id 失效；工具返回里带新 id，页面刷新即可。
