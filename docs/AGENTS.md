# 文档标准

本文件是本仓库文档的统一入口：说明各类文档的属主、位置和阅读路线。表中未加链接的路径从仓库管理根目录解析，Markdown 链接相对本文件。

每项事实只在一个属主里写全。写作和评审都先确认属主，其他位置只链接。

## 文档分层

下表用于识别内容归属，不要求逐类建立文档；不存在的内容不建空文件。

| 常见文档 | 通常负责什么 | 不重复承载什么 |
| --- | --- | --- |
| 作品指南 / README | 作品入口、阅读顺序与使用方式 | 已由工作项或合同完整拥有的约定 |
| 工作项（Proposal / Issue） | 本次交付范围、产品行为与验收、状态、评审与批准证据 | 长期技术决定的正文 |
| 独立 Spec（按需） | 跨工作项持续生效的行为合同、约束与可观察验收条件 | 讨论过程与技术方案全文 |
| Agent Note | 长期技术提案、真实备选、决定与后果 | 产品合同、工作状态、已有权威设计全文 |
| Domain 文档（术语表） | 领域术语、边界与关系 | 临时工作状态与实施步骤 |
| AGENTS.md / 技能 | Agent 行为规则、工作方法与仓库护栏 | 产品及运行时合同 |
| 作品正文与设定 | 章节、大纲、人物与世界观 | 工程决定与流程记录 |

## 项目归属配置

| 内容或类型 | 启用方式与适用范围 | 属主、位置与规则入口 |
| --- | --- | --- |
| 工作项（Proposal / Issue） | 已启用；本次交付范围、产品行为与验收 | GitHub Issues `dehuadong/dsh-nove`；创建、读取与状态约定见 [issue-tracker.md](agents/issue-tracker.md) |
| 工作状态、评审与批准证据 | 已启用；工作项推进 | 同一工作项 issue；`Status:` 行、评审与批准位置见 [issue-tracker.md](agents/issue-tracker.md) |
| 分诊角色标签 | 已启用；issue 分诊 | 角色到标签字符串的映射见 [triage-labels.md](agents/triage-labels.md) |
| 独立 RFC / ADR | 新工作未启用 | 技术设计与决定写 Agent Note |
| 独立 Spec | 按需启用；跨工作项持续生效的行为合同 | 首次需要时先登记属主、适用范围、位置与规则入口，再写正文 |
| Agent Note | 已启用；长期技术提案、设计、决定、备选与理由 | `.agents/notes/`（相对管理根）；单根，格式与生命周期由 `write-agent-notes` Skill 拥有，根范围与校验入口见 [.agents/notes/AGENTS.md](../.agents/notes/AGENTS.md) |
| 领域术语表 | 未建立；按需创建 | 单上下文，根目录 `GLOSSARY.md`；读取规则见 [domain.md](agents/domain.md) |
| 作品正文与设定 | 由各作品目录自有的文件拥有 | 各作品目录；本仓库文档不复制作品内容、口径与进度 |

已启用类型即使还没有记录也已登记位置。Agent Note 的格式、生命周期与 6 个固定分类由 `write-agent-notes` Skill 唯一拥有。

## 一个事实一个家

- 产品行为与验收归工作项；跨工作项持续生效的合同按需由独立 Spec 或已有规范拥有。
- 长期技术设计与决定归 Agent Note，工作项链接到 Note；Note 不反向记录工作进度。
- 工作状态、评审批准与执行授权是三件事：状态和证据归工作项，执行权限由工作区 [AGENTS.md](../AGENTS.md) 的授权门禁规定。
- 机器能生成的清单（目录、路由表、测试清单）不手抄，链接到源码或生成物。

## 写作规则

- 写当前状态：变更过程归提交与工作项，正文不写“已实现”“未来会”这类会腐坏的状态标注。
- 保留完整命题：删减前确认执行者、动作、条件、时序、义务强度、例外、副作用和失败后果仍在。
- 一节只讲一件事；一个段落一行，用软换行。
- 事实与推论分开：可核实的事实写明证据位置，推论、估计和待确认事项明确标注。
- 设计提案先写“对拍参考”：列参考工程 `inkos-master` 的证据位置与实现方式，再写我们的实现与裁决（采纳/等价适配/不采用及原因）；没有参考实现时写“无参考实现”、检索范围与理由。
- 复用 `GLOSSARY.md` 的术语，不为已明确弃用的概念换同义词。
- 注释只补充代码无法表达、读者必须知道的行为与约束；长期设计理由链接适用的已交付 Note。
- 新增或实质改写的文档使用相对链接；不复述属主已经写全的内容。

## Slop 清单

审阅时删改：同一规则出现多处；把历史写进当前规则层；手抄源码或生成器已拥有的清单；推理过程、显然分支推导、测试走演、评审记录与被否决的局部备选；注释复述代码；一段塞进多条规则；满篇加粗与“关键的是”。

## 检查

- Agent Note 的目录、头块、正文骨架与本地链接：从仓库管理根运行 `npm run verify-notes`。
- 机械检查通过不代替对事实归属、内容真实性与合同完整性的审阅。本仓库未配置 CI 或提交钩子。
