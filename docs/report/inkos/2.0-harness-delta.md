# InkOS 2.0 Harness 增量研究

基线：`inkos-master` 2.0.0（`package.json`；目录无 `.git`，旧报告里的 commit pin 无法复核）。本文只记录当前源码与 1.x 报告的差异，不重复 1.x 已写清的内容。

## 执行模型

- 作品是 canonical Work，目录 `works/<id>/`，`work.json` 记录 profile 与已注册 artifacts；`source/` 是工作文件。
- Studio、CLI、Agent 共用同一套 Work / Episode / Artifact 语义，不再区分“对话”和“生产线”两套写入路径（`spec/creative-harness-v2.md`）。
- 动作成功只由 `ActionResult` 证明：`status: "success"`、`summary`、可选 `content`、`artifacts[]`、`observations[]`；正文或总结不能证明落盘（`harness/contracts.ts:148-156`）。
- artifact 读取、审稿、导出固定 revision 并校验 checksum；缺文件返回可恢复的 typed lookup error（`spec/creative-harness-v2.md`）。

## Capability 与动作

- 工具名是 `capabilityId__actionId`，由 `createCapabilityPiTools` 按 profile 暴露（`harness/pi-tools.ts:84`）。
- `CapabilityAction` 带 `risk`（read / recoverable-write / destructive-write）、`requiresConfirmation`、`defaultSkillIds`、typed params 与 `execute`（`harness/capability-registry.ts:23-33`）。
- 失败时把 `code`、`resultTool`、`stopReason`、`attempts`、`recovery` 结构化回给模型；读取失败可在同一轨迹重试（`harness/action-observation.ts:4-27`, `pi-tools.ts`）。
- 这与 storycraft 的“固定 `story_*` 动作 + 宿主作者闸门”不同：InkOS 的权限层集中在 profile/capability，不能直接照搬。

## Profile 与确认

- 9 个内置 profile：`workspace-default`、`longform-novel`、`short-fiction`、`script`、`storyboard`、`interactive-film`、`interactive-world`、`translation`、`visual-asset`（`harness/builtin-profiles.ts:6-71`）。
- `WorkProfile` 字段：`capabilityIds`、`requiredSkillIds` / `recommendedSkillIds`、`artifactKinds`、`confirmation`、`contextRecipe`、`artifactSchemas`、`qualityCriteria`、`production`（`harness/contracts.ts:116-131`）。
- profile 决定“哪些动作工具存在”，不是只决定推荐技能；这是 1.x 报告没有覆盖的。
- `ConfirmationPolicy` 分 inferred mutation、explicit recoverable mutation、destructive mutation；destructive 固定 `confirm`。
- `propose_action` 把 action、target session kind、same-session、requested skills、payload 交给作者确认；确认后由源会话/入口执行（`agent/agent-tools.ts:647-693`）。

## Session 与入口

- `sessionKind` 映射到 profile，例如 `book`/`book-create`/`edit` → `longform-novel`，`short` → `short-fiction`，`play` → `interactive-world`（`harness/session-binding.ts:4-15`）。
- 会话绑定 work 后才生产；对话结束不等于交付完成（`spec/creative-harness-v2.md`）。
- CLI 显式动作复用同一 Episode runtime（`harness/explicit-action.ts`），不是另一套 runner。

## Skill 与资源

- 20 个技能包、18 份 references；长篇 `inkos-long-writing` 有 4 份参考（foundation、reader contract、scene/length、state projection）。
- 技能发现支持 `INKOS_SKILL_DIRS`、用户级 `~/.openclaw/skills` / `~/.agents/skills`、项目 `.agents/skills` 与 `skills/`，并限制深度与总大小（`skills/external-loader.ts:95-127`）。
- `use_skill` 支持 `resourcePath` 精确读取，也支持 `query` 在技能 references 内检索；只加载说明，不授予工具/权限（`agent/skill-tool.ts:20-80`）。
- 每轮可带 `requestedSkills` / `disabledSkills`（`@skill-id`），技能激活不永久污染后续轮次（`agent/agent-session.ts:98-105`）。
- 检索已归一为一个本地内核，故事记忆、材料、Skill references 按 scope/kind 区分（`retrieval/local-search.ts:28-30`）；1.x 的“方法检索与作品检索是两套系统”已过时。
- 资源绑定：book reference 带 `uses` 用途，材料有 `purpose`，Composer 在预算内合并（`references/book-references.ts:9-19`, `materials/ingest.ts:20-35`）。

## Agent 与交接

| 环节 | 2.0 行为 | 交接证据 |
| --- | --- | --- |
| architect | 三段式生成 story_frame / volume_map / book_rules / 角色卡 / 初始伏笔，原子 commit | `agents/architect.ts:142-184,262-344` |
| planner | Composer 选上下文 → ChapterIntent + ChapterMemo，写 runtime intent | `agents/planner.ts:46-117` |
| composer | 半窗预算、语义选择、outline/memory/reference 合并 | `agents/composer.ts:308-384` |
| writer | memo + context → 正文；提交后做 runtime state delta / summary | `agents/writer.ts:100-140,271-363` |
| state-validator | 比较旧/新投影与权威，最多一次 reconciliation，失败保留正史 | `agents/state-validator.ts:28-97`; `pipeline/chapter-truth-validation.ts:80-127` |
| continuity | observation code + 行号证据 | `agents/continuity.ts:28-104` |
| reviser | observation/instruction + mode；spot-fix 有行范围契约 | `agents/reviser.ts:32-130` |

结论：InkOS 把“状态投影”和“投影对账”放在 writer 之后、finalize 之前；architect/planner 是独立委派角色。storycraft 当前没有这两段。

## 生产线

2.0 profile 覆盖 longform、short、script、storyboard、interactive-film、interactive-world、translation、visual；对应 agent/runner 明显多于 1.x 报告：

- `short-fiction.ts`、`script-storyboard.ts`、`play/`、`translation/`、`forecast/`；
- `researcher.ts` 是函数式研究入口，`radar.ts` 负责趋势来源；
- `style-guide.ts`、`production-document-tool.ts` 支撑生产文档。

这些不在 storycraft 当前主线，但报告不能再用“只有长篇 + 审稿 + 修订”的 1.x 框架概括 InkOS。

## 旧报告中已过时的结论

1. **Profile = 技能 + artifact 类型**：漏了 capability gate、confirmation、contextRecipe、artifactSchemas、production。
2. **只有包内技能**：实际有外部目录、项目技能、per-turn 强制/禁用、reference 检索。
3. **两套检索**：已统一为一个内核。
4. **约 14 个技能、5 个域**：实际 20 个技能、18 份 references，且 `inkos-story-deslop` 未出现在旧报告。
5. **L4 的 Coordinator + PipelineRunner 框架**：无法覆盖 capability 动作、确认提案、session→profile 绑定与完成证据，需要以 Harness/Episode 视角读。
6. **commit pin**：目录无 `.git`，旧 pin 不能作为当前基线；以 2.0.0 + 源码为准。

## 对 storycraft 的增量含义

- 最该借的是**交接位置**，不是权限层：architect foundation、planner memo、writer 后 settler、validator 对账。
- 最该补的资源是长篇三份方法参考（foundation、reader contract、state projection）与形态路由（form → skill）。
- 不复制 capability gating / `propose_action` / Profile 注入；storycraft 已有动作白名单、作者闸门与委派回执。
- 具体差距、优先级与不采纳项见 `pipeline/2026-10-18-storycraft-parity-matrix.md`；阶段排期见 `workspace/2026-10-19-storycraft-roadmap.md`。
