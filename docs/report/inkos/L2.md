# InkOS 深度研究报告：L2 Skill 内容体系

独立专题 · 文学方法、专业知识组织与资源设计 · 2026-10-21

研究对象： InkOS 的 `master` 分支，重点为 `packages/core/skills/` 的专业 Skill 原文及 References。

研究边界： 本报告研究 Skill 中真正包含什么创作知识、这些知识如何组织、如何覆盖不同创作阶段、各类资源承担什么职责。Runtime 加载及 Agent 调用仅在需要解释内容组织时涉及，不重复 L6。

## 一、核心研究结论

本轮直接读取了 12 份代表性专业 Skill，以及长篇创作、故事审阅、短篇生产、市场研究对应的 6 份 References。

相比此前 L1 + L2 的联合研究，本轮发现更值得注意的一点：

InkOS 的 Skill 内容体系不是传统意义上的“写作教程库”，而是以创作任务为边界、以文学因果和读者体验为核心、以阶段化 References 补充细节的专业方法体系。

从实际文件可以看出，它具有四项鲜明特征：

1. Skill 主体相对精简。主要描述专业原则、创作边界和常见失败模式，而非在主文件中堆砌完整教程。
2. References 承载深入方法。例如长篇写作将基础设计、读者期待与连载推进、章节事实投影分成独立资源。
3. 文学方法围绕“可观察的变化”组织。人物选择、情节推进、伏笔兑现、关系变化和场景结果必须在实际叙事中体现，而不是在计划或说明里宣称完成。
4. 专业知识和执行合同存在交叉。部分 Skill 不只讲文学创作，还包含状态更新、来源权威、修订范围和内容生命周期等操作约束。

第四点尤其值得深入辨析：这类约束有些属于创作专业知识，有些其实是系统状态语义，二者并不完全等价。

### L2 的总体内容结构

根据已检查的 Skill 内容归纳，不表示 InkOS 源码具有一套同名的知识分类枚举。

## 二、L2.1：专业 Skill 如何分类

InkOS 使用统一 Skill 格式，但内容并不是围绕单一小说写作流程堆积的。

从已读取的文件看，可分为五个专业领域。

| 专业领域    | 代表 Skill                                                          | 核心知识                   |
| ------- | ----------------------------------------------------------------- | ---------------------- |
| 长篇叙事    | `inkos-long-writing`、`inkos-story-review`                         | 场景、人物、连载推进、审稿与修订       |
| 短篇商业叙事  | `inkos-short-writing`                                             | 核心冲突、完整兑现、反转、短篇包装      |
| 剧本及视觉叙事 | `inkos-script-writing`、`inkos-storyboard`                         | 可表演场景、镜头语言、空间与视觉连续性    |
| 互动叙事    | `inkos-interactive-film`、`inkos-play-world`                       | 分支、选择、状态、可达性、玩家行动      |
| 衍生与专业辅助 | Fanfic、Continuation、Spinoff、Imitation、Translation、Market Research | 来源正典、续写边界、文风迁移、术语及市场证据 |

这些类别具有共同的文学基础，但各自的专业知识并不完全相同。

例如：

长篇写作的核心是持续推进人物、冲突与读者期待；短篇的核心是有限篇幅内完成情绪和因果闭环；剧本需要将内心活动转成可表演的行动；互动作品还必须考虑不同选择路径下的状态一致性。

### 2.1 专业领域分类，不等于执行阶段分类

这是此前联合研究没有充分区分的地方。

`inkos-long-writing` 并不只用于 Writer，其原文明确允许在 Architect、Writer、Auditor、Reviser 等不同操作中应用。

同一个 Skill 可以服务多个阶段，但专业原则根据任务产生不同作用。

| 阶段   | 同一长篇 Skill 的主要关注点 |
| ---- | ----------------- |
| 基础设计 | 中心冲突、人物成长、卷终变化    |
| 章节规划 | 场景目标、读者承诺、叙事推进    |
| 正文写作 | 动作、阻力、转折、后果       |
| 审阅   | 因果、节奏、人物动机和兑现情况   |
| 修订   | 找到真正问题并选择最小有效修复   |
| 状态结算 | 保留正文实际发生的变化       |

因此，InkOS 倾向于将文学方法按创作专业领域组织，而非为每个 Agent 完整复制一套写作规则。

这能够减少重复，但也产生新的要求：不同阶段必须正确选择和解释同一专业原则。

## 三、L2.2：长篇 Skill 主体究竟指导什么

核心文件：

[inkos-long-writing/SKILL.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-long-writing/SKILL.md)

我将其内容进一步按文学机制拆开。

### 3.1 场景的最小叙事单元

Skill 要求场景具有：

目标

Objective

阻力

Resistance

转折

Turn

后果

Consequence

这里关注的不是场景是否包含一定数量的对话或动作，而是场景结束后是否留下了持续影响。

这背后有一条非常重要的文学判断：

场景存在的价值来自叙事状态的变化，而不是篇幅、描述数量或形式上的戏剧性。

例如，角色进入酒楼、点菜、聊天，如果没有改变冲突、信息、人物关系或后续后果，在 InkOS 的方法中就可能属于无效扩写。

但安静场景并不天然无效。只要人物理解发生变化、关系产生细微位移，仍然有叙事价值。

### 3.2 人物因果机制

长篇 Skill 没有简单要求“人物要立体”，而是让人物选择受到四个方面制约：

| 变量         | 实际意义      |
| ---------- | --------- |
| Wants      | 人物想得到什么   |
| Knows      | 人物当时知道什么  |
| Fears      | 人物害怕失去什么  |
| Can afford | 人物能承担什么代价 |

这是一种强调选择合理性的人物方法。

例如，一个角色做出了违背其既定利益的选择，不能仅用“他突然感动了”解释。需要有新的事实、情绪变化、关系约束或不可回避的代价，使该选择在当时成立。

这一原则同时适用于规划、写作和审稿。

### 3.3 叙事信息控制

Skill 要求通过行动、证据、对话、感官细节释放设定和背景，而不是用大段总结替代场景。

同时强调不能为了制造反转，故意隐藏视角人物本应知道的信息。

这里涉及两种信息权利：

- 人物知识边界：角色在当前时间点知道什么。
- 读者信息边界：作者选择在何时让读者获得什么。

二者可以不同，但不能无理由地冲突。

例如，悬疑可以让读者不知道凶手身份，却不宜让一个明明已掌握关键答案的视角人物在内心叙述中刻意绕开答案，只为最后一页强行制造反转。

### 3.4 文学质量的负面约束

长篇 Skill 明确反对一些常见问题：

- 为达到字数而重复解释或注水。
- 用旁白评价代替人物具体行为。
- 用机械断章公式制造悬念。
- 让所有群众同步作出同样反应。
- 用无理由的巧合或角色降智解决冲突。
- 在润色任务中擅自改变人物决定和剧情因果。

这些规则的重要性，不在于数量，而在于它们对应明确的失败模式。

因此，主 Skill 实际上由两类知识构成：

正向构造方法：怎样设计有效场景、人物行为和叙事推进。

负向质量边界：哪些创作捷径会破坏因果、节奏、人物可信度或作者既定方向。

## 四、L2.3：References 如何承载深层文学方法

本轮阅读发现，长篇写作 Skill 具有三份作用不同的核心资源。

[foundation-design.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-long-writing/references/foundation-design.md)

负责作品基础设计：中心冲突、前景与深层因果线、世界规则、卷结构、人物弧光、核心伏笔及衍生创作。

[reader-contract-and-progression.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-long-writing/references/reader-contract-and-progression.md)

负责章节与连载推进：开篇、读者承诺、多轴变化、章节循环、因果所有权和信息连续性。

[state-projection.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-long-writing/references/state-projection.md)

负责章节事实提取：人物认知、状态变化、伏笔生命周期、状态投影以及资源变化的一致性。

### 4.1 Foundation：作品如何具备长期叙事能力

`foundation-design.md` 关注的不是先生成多少章节提纲，而是作品是否存在可以长期持续推进的叙事引擎。

其重点包括：

- 中心冲突是否来自不同人物之间真实的不兼容目标。
- 前景故事和深层故事是否存在因果连接。
- 每一卷是否有可观察的终点和不可逆变化。
- 主角的成长是否具有起点、方向和代价。
- 配角是否有独立的合作、反抗和误判动机。
- 核心伏笔是否存在可信的回收区域。

特别值得注意的是“前景线与深层因果线”的区分。

前景线负责让读者看到正在发生的冲突，深层线决定这些冲突为什么产生以及最终指向什么。

这种方法避免长篇小说只靠不断增加事件来维持篇幅。

### 4.2 Progression：如何验证真正的连载推进

`reader-contract-and-progression.md` 提出了一个比“每章有爽点”更完整的结构。

章节应该同时关注多个变化轴：

| 推进轴                | 可能发生的变化      |
| ------------------ | ------------ |
| Plot               | 冲突位置或任务进展    |
| Knowledge          | 人物或读者获得新信息   |
| Relationship       | 合作、对立、信任变化   |
| Status             | 身份、地位、社会评价变化 |
| Danger             | 风险范围或紧迫程度变化  |
| Resources          | 资源与行动能力变化    |
| Self-understanding | 人物对自身的认识变化   |

资源建议每章至少有一个主要推进轴及一个辅助推进轴。

这属于商业连载的专业建议，不是所有文学作品必须执行的硬门槛。

更重要的是它强调：

“提到某条故事线”不等于“推进了某条故事线”。

例如，连续三章都说“主角担心朋友遇险”，如果没有新的证据、决定、行动或关系变化，这条故事线可能并没有实质推进。

### 4.3 State Projection：内容理解与状态更新之间的边界

`state-projection.md` 明确要求：

- 只提取正文实际确立的事实。
- 不把规划当作已经发生的事件。
- 保持人物认知边界。
- 复用真实 Hook ID。
- 区分伏笔提及、推进、兑现、延期和被替代。
- 不因某个伏笔暂时未出现，就推断它已经废弃。

这一份资源与其他两份明显不同。

Foundation 和 Progression 主要是文学构造知识；State Projection 则更多是将文学文本转化为结构化状态时的解释规则。

所以它并不是单纯的“写作技巧”，而是文学语义与运行状态之间的桥接知识。

## 五、L2.4：人物弧光的知识表达是否足够深入

此前联合研究将人物弧光作为一个普通主题，深度确实不足。

本轮从 Skill 原文看，InkOS 对人物弧光的指导分散在三个位置：

| 来源                                   | 指导重点                     |
| ------------------------------------ | ------------------------ |
| `inkos-long-writing`                 | 人物选择必须与欲望、认知、恐惧、代价相符     |
| `foundation-design.md`               | 人物成长需要初始状态、内外目标、不可逆代价    |
| `reader-contract-and-progression.md` | 成长需要通过行动、关系、认识等实际变化体现    |
| `review-matrix.md`                   | 审阅时判断人物动机、声音、情感变化和已发生的推进 |

从文学逻辑上，这四项能够组成以下链路：

1

人物初始状态

身份、性格、认知、关系、缺陷与欲望

2

外部压力与内在冲突

现实目标与内部需求发生矛盾

3

受限条件下的选择

人物必须行动，并承受取舍

4

选择产生后果

关系、身份、信念或资源发生变化

5

不可逆的成长或退化

人物无法简单恢复为故事起点的自己

不过，需要进一步区分方法完整性与方法深度。

InkOS 已经说明人物弧光由什么构成，但这些资源并未提供一套完整的长期弧光设计方法，例如：

- 如何区分人物的表层欲望与深层需求；
- 如何规划信念受到逐级挑战的过程；
- 主角、配角和对手的成长曲线如何产生结构性对照；
- 人物在不同卷中如何反复面对同一内在问题，却作出不同选择；
- 如何检测人物变化过早、停滞或突然跳跃。

这些问题部分可以从现有原则推导，但尚未作为独立、深入的专业知识体系明确展开。

结论：人物弧光在 InkOS 中是核心创作原则，但不是已经高度细化的独立弧光方法模块。

## 六、L2.5：故事节奏与读者期待体系

这一部分主要依据 `reader-contract-and-progression.md`。

### 6.1 InkOS 将读者期待视为一种持续承诺

开篇建立的不只是悬念，还包括读者对作品会提供何种体验的预期。

例如，读者可能期待：

- 主角如何克服当前困境；
- 两个人物的关系如何改变；
- 某个隐藏事实何时被揭露；
- 一条长期冲突如何升级和结束。

InkOS 强调后续章节需要通过具体事件不断回应这些期待。

期待可以延期、加深或兑现，但不能只靠不断重复期待本身维持故事。

### 6.2 开篇三章的指导

资源中明确提出了商业连载开篇的阶段性建议：

| 阶段  | 内容目标                     |
| --- | ------------------------ |
| 第一章 | 在移动端第一屏出现具体扰动、矛盾、风险或未解事实 |
| 第二章 | 通过可见行动表现主角独特的能力、信息、约束或筹码 |
| 第三章 | 让读者能够理解主角下一步的短期目标        |

注意，文件本身明确指出这些属于商业连载创作默认建议，不能覆盖用户选择的文学节奏或作品形式。

这体现了 Skill 的一个良好语义边界：

文学惯例是专业建议，不应自动变成对作者意图的强制覆盖。

### 6.3 节奏不是持续升级

InkOS 强调短叙事周期，而不要求每章比上一章更加激烈。

一个合理周期可以包含：

建立压力

冲突升级

阶段兑现

结果余波

其中“兑现之后必须有余波”是一条值得注意的专业原则。

如果一次重大冲突刚刚解决，立刻开始更大危机，而人物没有时间对结果产生反应，那么故事可能虽然事件密集，却缺少情感重量。

### 6.4 当前知识体系的深度边界

InkOS 已较清楚地表达节奏与推进的关系，但没有在已检查的 References 中形成一套独立的节奏分析学体系。

例如，尚未看到系统化展开：

- 场景节奏、章节节奏、卷节奏之间的嵌套关系；
- 张力、信息密度与情绪消耗的相互作用；
- 不同题材读者对等待和兑现的容忍差异；
- 如何判断一次反转是否过密；
- 如何处理多个故事线之间的节奏错位。

这不代表 InkOS 完全不能处理这些问题，而是当前 Skill 内容没有将它们详细形式化。

## 七、L2.6：审阅 Skill 的专业标准体系

核心文件：

[inkos-story-review/SKILL.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-story-review/SKILL.md)

参考资源：

[review-matrix.md](https://github.com/dehuadong/inkos/blob/master/packages/core/skills/inkos-story-review/references/review-matrix.md)

### 7.1 审阅方法并不是通用评分表

`inkos-story-review` 规定先确定适用标准：

- 题材；
- 目标读者；
- 风格和语气；
- 发布平台；
- 作者明确偏好。

然后才开展具体审阅。

其 References 还针对不同题材设置不同的判断重点。

| 类型   | 特别重视的内容              |
| ---- | -------------------- |
| 喜剧   | 铺垫、节奏、夸张是否符合人物逻辑     |
| 爱情   | 关系变化、潜台词、情绪可信度       |
| 悬疑   | 证据可见性、公平推理、信息控制      |
| 商业连载 | 持续阅读压力与场景完整性         |
| 文学作品 | 感知、语言、主题变化，不机械要求高速情节 |

这种方法比“所有作品统一按节奏、冲突、爽点打分”更灵活。

### 7.2 审阅维度

`review-matrix.md` 的主要审阅方向可以整理为：

| 维度     | 核心问题            |
| ------ | --------------- |
| 意图一致性  | 是否遵守作者目标和持久约束   |
| 因果与连续性 | 事件是否符合既有事实和逻辑   |
| 人物     | 动机、声音和行为是否成立    |
| 场景     | 是否有明确功能及后果      |
| 信息     | 证据、认知与信息释放是否可信  |
| 文字     | 表达清晰度和叙事视角稳定性   |
| 情绪     | 作品承诺的体验是否真正兑现   |
| 长篇推进   | 当前章节是否推进故事及读者承诺 |

尤其强调：审阅必须区分客观矛盾与审美偏好。

例如，角色同时出现在两个不可能同时到达的地点，属于可以定位的连续性问题。

但“我认为此处应该更激烈”，可能只是审美偏好，必须结合作者选择、题材与文本证据判断。

### 7.3 修订层级分类

审阅资源明确提出三种修复范围：

- `local`：句子或局部段落。
- `structural`：场景、时间线、因果、视角、人物逻辑或重大兑现问题。
- `unknown`：证据尚不足以判断。

这里的专业知识不是“发现问题就重写”，而是先判断问题位于哪一层。

这是一种问题诊断知识体系，而不是简单的修改提示词。

### 7.4 审阅内容的不足

虽然审阅矩阵覆盖面较广，但其内容仍偏定性。

例如，它要求检查人物动机、节奏和情绪兑现，但没有为每项提供完整的证据模式、判定阈值、误判示例和问题严重度分级。

同样，没有充分展开：

“同一文学问题在什么情况下应接受为风格选择，而不是缺陷？”

这限制了审阅标准在不同模型与不同场景中的一致性。

## 八、L2.7：短篇、剧本与互动叙事为何需要独立专业 Skill

这一部分能够解释 InkOS 为什么没有把所有内容创作知识集中在一个万能写作 Skill 中。

### 8.1 短篇：完整性优先于无限延展

`inkos-short-writing` 将重点放在：

- 一个能够支撑全篇的核心冲突；
- 可信的反转与证据；
- 开篇冲击；
- 每一章实际发生的叙事变化；
- 结局完成既定情感兑现；
- 标题、简介和包装必须忠实于真实正文。

其 `production-checklist.md` 进一步强调时间、金额、年龄、证据链及物品流转的一致性。

这说明商业短篇不仅需要故事吸引力，还非常依赖一次性完成整个因果闭环。

相比之下，长篇可以通过卷与短周期持续建立和兑现多个承诺。

### 8.2 剧本：把不可表演的内容转成可见动作

`inkos-script-writing` 明确要求将内心独白转换为：

- 行为；
- 对话；
- 走位；
- 道具；
- 证据；
- 声音；
- 可见后果。

这是媒介转换知识，而不仅是修改排版格式。

小说可以直接写“她已经不再相信他”，但剧本需要让不信任体现在选择、动作、反应或对话中。

### 8.3 分镜：以镜头表达戏剧功能

`inkos-storyboard` 强调每个镜头都应具有：

- 叙事目的；
- 可见主体；
- 动作；
- 空间关系；
- 镜头大小或摄影机行为；
- 前后连续性。

它反对把小说逐句机械拆成镜头。

这是一套视觉叙事的取舍原则，而不是图像提示词模板。

### 8.4 互动内容：状态和选择成为故事语法

`inkos-interactive-film` 与 `inkos-play-world` 的内容尤其值得区分。

互动影游关注分支、选择、条件、变量、合流和结局可达性。

开放世界 Play 关注玩家已选择的行动、场景状态、时间推进、实体身份、物品位置以及角色的自主行为。

例如，互动影游要求每条可到达路径都能正确进入合流节点，而不是将互斥事实无条件写在共享场景中。

这类知识不能简单复用传统小说的“场景目标—阻力—转折”方法，因为它还需要保证不同状态下的叙事可执行性。

## 九、L2.8：衍生创作 Skill 的共同知识核心

InkOS 还分别提供同人、续写、番外和仿写 Skill。

这些 Skill 看起来相近，但其专业关注点并不相同。

| 创作类型         | 内容权威       | 新创作空间         | 核心约束            |
| ------------ | ---------- | ------------- | --------------- |
| Fanfic       | 导入的原作正典    | 原作空白、AU 或授权偏离 | 角色、世界及时间线不能无意冲突 |
| Continuation | 已有正文和延续时点  | 已建立故事的后续      | 不重置人物认知及已发生事件   |
| Spinoff      | 母本 Work 正典 | 独立侧篇          | 不擅自改变母本主线事实     |
| Imitation    | 用户新作品的创作意图 | 全新故事          | 只迁移文体方法，不复制源故事  |

其中最重要的共同原则是：

参考来源提供已确认的事实或可迁移的方法，但不应该自动取得对新作品一切内容的决定权。

尤其是 `inkos-imitation-writing`，明确把可迁移的文风特征与不可复制的故事表达区分开。

它关注叙事距离、句式变化、段落节奏、对话密度、感官选择、幽默及信息释放，而不是照搬参考作品的人物和剧情。

这表明 InkOS 的内容体系里，已经意识到“借鉴文学方法”和“继承内容事实”属于不同的操作。

## 十、L2.9：Skill 主体与 References 的分工是否清楚

从目前读到的文件看，InkOS 没有采用“每个 Agent 一个大型指导文档”的方式。

其主要结构为：

```
packages/core/skills/
  inkos-long-writing/
    SKILL.md
    references/
      foundation-design.md
      reader-contract-and-progression.md
      state-projection.md

  inkos-story-review/
    SKILL.md
    references/
      review-matrix.md

  inkos-short-writing/
    SKILL.md
    references/
      production-checklist.md

  inkos-long-market-research/
    SKILL.md
    references/
      research-rubric.md
```

以上是本次已核验的代表性目录，不是完整的内置 Skill 目录清单。

### 10.1 主体负责共同原则

SKILL.md 主要回答：

- 哪种任务应该使用这项专业方法；
- 该领域必须遵循什么原则；
- 常见的失败模式是什么；
- 何时需要更深入的资源。

### 10.2 References 负责细分方法

References 主要回答：

- 特定阶段应该怎样设计和检查；
- 需要观察哪些叙事变化；
- 怎样区分不同类型的问题；
- 哪些内容不能凭空推断；
- 修订时应该保留什么。

### 10.3 但知识边界并非完全干净

例如，`inkos-long-writing` 主体既有一般文学规则，也有旧规划失效、Hook 复用及历史变更等状态语义。

`state-projection.md` 则包含了相当具体的运行状态操作含义，例如被替代的伏笔如何保留原 ID，何种情况才允许标记 `superseded`。

这些规则能够指导模型正确理解文学事实，但又不完全属于传统写作技法。

所以 InkOS 实际上是一个混合型专业知识体系：

文学创作方法

场景、人物、节奏、情绪、叙述、读者期待

媒介与题材方法

长篇、短篇、剧本、互动、翻译、衍生

专业诊断方法

内容审阅、问题归因、修订范围判断

内容状态语义

正史边界、角色认知、伏笔身份、事实演化

工作交付约束

阶段输入、结果真实性、输出形式与任务边界

这不是简单的设计错误。文学内容生产本身就具有高度语义化的状态管理需求。

但需要认识到：越是接近运行状态完整性和版本安全的规则，仅依赖 Skill 文本就越不足够。 对应程序合同仍然有必要。

## 十一、L2.10：内容分类的完整研究矩阵

将已读取的专业知识按照创作阶段和内容类型统一归纳：

● 有明确方法覆盖　◐ 有原则覆盖或间接指导　— 本轮未见专门展开

| 专业知识      | 基础设计 | 规划 | 创作 | 审阅 | 修订 |
| --------- | ---- | -- | -- | -- | -- |
| 故事核心冲突    | ●    | ●  | ◐  | ●  | ◐  |
| 人物动机与弧光   | ●    | ●  | ●  | ●  | ◐  |
| 场景目标与转折   | ◐    | ●  | ●  | ●  | ●  |
| 读者承诺与兑现   | ●    | ●  | ●  | ●  | ◐  |
| 连载节奏与结构   | ●    | ●  | ●  | ●  | ◐  |
| 文风与叙述视角   | ◐    | ◐  | ●  | ●  | ●  |
| 历史事实连续性   | ◐    | ●  | ●  | ●  | ●  |
| 伏笔生命周期    | ●    | ●  | ●  | ●  | ◐  |
| 情绪推进      | ●    | ◐  | ●  | ●  | ◐  |
| 证据与信息释放   | ◐    | ●  | ●  | ●  | ●  |
| 精准修订范围    | —    | —  | —  | ●  | ●  |
| 跨章节整体质量趋势 | ◐    | ◐  | ◐  | ◐  | —  |

这份表反映的是知识文件的覆盖，不表示每个对应 Agent 在实际运行中必然加载全部相关资源。

一个重要结论是：

InkOS 对场景、因果、读者承诺和连续性的指导相对密集；对全书范围的人物弧光追踪、情绪曲线建模及跨章节文学质量趋势，则更偏原则性指导。

## 十二、L2.11：专业方法如何从知识变成可操作判断

可以把 Skill 的内容质量分成四个深度等级。

| 深度       | 内容形式        | InkOS 示例               |
| -------- | ----------- | ---------------------- |
| D1：价值原则  | 说明什么是好的叙事   | 人物行为应当可信               |
| D2：构造方法  | 说明应该怎样组织    | 场景需要目标、阻力、转折和后果        |
| D3：诊断条件  | 指明怎样发现失败    | 重复提及一条故事线不等于推进         |
| D4：修复与验证 | 说明怎样纠正并确认结果 | 局部文字问题小范围修订，因果问题需结构性处理 |

从已检查的内容看，InkOS 的知识体系并不停留在 D1。

例如：

- 长篇场景设计达到 D2。
- 连载推进与人物因果包含 D3。
- 审阅矩阵的修复范围指导包含 D4 的一部分。
- 状态投影对于 Hook ID 和事实变化提供较具体的诊断条件。

不过，它的 D4 仍不完整。

例如，`review-matrix.md` 可以要求检查人物弧光，但是未提供一套完整方法来验证人物弧光的每个关键变化是否已通过前序场景获得充分铺垫。

换言之：

InkOS 的专业知识具有较强的生成指导和问题识别能力，但对复杂文学问题的多阶段修复验证仍缺乏充分细化的独立方法库。

## 十三、L2.12：知识组织对模型使用效果的实际影响

这里需要结合内容写法判断，而不是重复 L6 的工具调用研究。

### 13.1 简短 Skill 的优势

InkOS 主 Skill 通常是高度压缩的专业原则。

其优势是便于在不同任务中重复使用，不必每次加载完整的写作教程。

但潜在问题是：

某些短原则对专业创作者具有明确意义，对模型却可能留下较大解释空间。

例如，“人物弧光要付出不可逆代价”是有价值的原则，但如何判断代价足够可信，需要额外的具体方法与证据。

### 13.2 分阶段 References 的优势

把基础设计、叙事推进和状态投影分开，有利于根据当前操作提供相关知识。

而且 InkOS 主 Skill 已显式引用相关文件。

需要注意一个技术细节：此前 L6 读取的 `loadLinkedSkillResources()` 会识别 SKILL.md 中符合规则的 `references/` 链接。

因此，上述长篇 Skill 的静态引用不仅是面向人类阅读的目录，还能成为 Runtime 的资源加载入口。

不过，当前链接解析不会仅凭自然语言中“规划阶段才需要”这一描述，就自动理解全部阶段条件。

从已检查的代码看，链接资源可以被主动加载，再结合任务检索补充。

所以，阶段化资源组织与阶段化实际注入不是完全相同的事情。

### 13.3 专业方法复用也可能导致上下文混杂

一个跨 Architect、Writer、Auditor、Reviser 共用的 Skill，如果主体内包含所有阶段的约束，就可能出现：

- Writer 收到本应主要用于状态结算的指导；
- Auditor 收到不适合审阅阶段的创作建议；
- Reviser 需要区分润色规则与剧情重构规则。

InkOS 通过当前任务、Skill 主体和专业 References 来控制这些语义，但并未在已读取的主文件中将所有内容拆成严格机器可识别的阶段合同。

这是内容组织与实际消费之间需要区分的边界。

## 十四、L2 内容体系的深度评估

以下是对已检查 Skill 的定性研究结论，不是官方质量评分。

| 研究维度        | 评价     | 理由                 |
| ----------- | ------ | ------------------ |
| 任务定位        | 较成熟    | Skill 的专业领域和使用边界明确 |
| 主 Skill 精简性 | 较成熟    | 没有重复堆叠大型教程         |
| 专业领域划分      | 较成熟    | 长篇、短篇、剧本、互动等有明显差异  |
| 文学因果方法      | 较成熟    | 强调行动、选择、信息与真实后果    |
| 连载推进方法      | 有较明确体系 | 读者承诺、多轴推进、短周期及余波   |
| 人物弧光深度      | 中等     | 有构造原则，缺少完整长期弧光方法   |
| 场景结构深度      | 中等     | 四要素清晰，细分场景类型较少     |
| 情绪设计        | 中等偏基础  | 注重兑现与可信度，缺少细化曲线方法  |
| 题材专门方法      | 部分成熟   | 有差异化审阅，但深度不均       |
| 审阅诊断        | 较成熟    | 依据证据、区分审美与客观问题     |
| 修订指导        | 部分成熟   | 修订层级明确，专项修复方法有限    |
| 专业知识效果验证    | 尚未证实   | 不能从文档内容推导真实生成效果    |

本次发现最明显的三个不足，不是简单“Skill 数量不够”，而是：

一、深入的文学方法仍不均衡。 场景因果和连载推进指导比较具体，人物弧光、情绪组织、复杂叙事结构的专项深度仍有提升空间。

二、方法、审阅标准和修复机制没有全部形成一一对应。 一条写作规则存在，不代表审阅资源已给出充分的证据标准，更不代表修订资源明确说明怎样纠正。

三、内容知识和状态操作约束存在混合。 这种设计有实际必要性，但需要清楚区分文学判断与程序应该保证的事实一致性。

## 十五、L2 最终研究结论

InkOS 的 Skill 内容体系可以总结为以下五层知识：

K1：叙事基础原则

场景必须发生变化，人物选择有因果，故事承诺需要兑现。

K2：作品形式与题材方法

长篇、短篇、剧本、互动作品及衍生内容的专业差异。

K3：创作阶段专项方法

基础设计、章节推进、状态投影、审阅和修订。

K4：质量诊断与修复原则

问题类型、文本证据、修订范围及原因定位。

K5：内容权威与状态语义

正史、来源、人物认知、伏笔生命周期及既成事实。

K1—K5 是本轮研究归纳的知识层次，并非 InkOS 官方命名。

这五个层次的关系，是本轮独立研究的重要成果。

InkOS 真正有价值的地方，不在于把大量写作教程放进 Skills，而在于把能够指导具体创作决策的规则提取出来，使其围绕任务、作品类型和叙事状态发挥作用。

但它也还不是一套涵盖所有文学创作技能、具备完善案例与验证标准的完整专业知识库。

目前更准确的定位是：

一套精简、任务导向、重视叙事因果与连续性的内容创作方法体系，辅以阶段性专业参考资料。

本轮对内容体系进行了独立深入研究，但未做真实 LLM 的生成效果对照，也未穷举全部内置 Skill。因此，不能将“内容机制设计合理”直接等同于“创作质量已经得到验证”。
