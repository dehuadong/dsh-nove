# 长篇小说单章写法

一个章节只追求一件事：让读者在读完后有明确的“接下来会怎样”的期待，同时不破坏已经建立的人物与事实。

## 开工前必须先读

1. `作品目录` 下的设定与大纲：世界观、人物卡、卷纲、章纲。缺哪份就明说缺哪份，不要凭空补设定。
2. 上一章正文的结尾段落。上一章怎么收，直接决定本章怎么起。
3. 已埋伏笔清单（若有）。本章要么推进一条伏笔，要么种下一条，不要两条都不动。

读不到的东西不要编造。缺设定时先问用户，或先给出“需要补充的三项设定”再动笔。

## 写作流程

1. **定章纲**：先用三到五行写清本章的：视角人物、本章目标、阻力、代价、结尾变化。用户没有章纲时，先给出章纲让用户确认，再写正文。章纲用 `story_plan` 落盘，五项缺一会被拒绝。
2. **分场景**：一章拆二到四个场景，每个场景写清进入状态与退出状态。场景之间必须有时空或因果推进，不能原地打转。
3. **写成稿**：按场景顺序写，场景内允许留白，不允许解释设定。人物知道的与读者知道的要分清。正文用 `story_write` 落盘。
4. **自检**：对照下面的自检清单逐条看，能改的直接改，改不了的写进“待确认”。
5. **审稿与修订**：发现写成问题清单交给 `story_review`（只落盘清单，不动正文）；按条目改稿用 `story_revise`，它生成新版本并把处理的条目标为已处理。
6. **状态结算**：把本章产生的新事实交给 `story_state`（人物状态、关系、时间线、已用伏笔、未解悬念），只写变化，不重抄全部设定。

## 输出契约

- 正文、章纲、审稿清单、状态一律由动作落盘，不要用文件工具直接写 `works/` 下的产物：动作负责版本、进度清单与原子性，直接写会让进度与文件不一致。
- 动作对应：`story_init` 立项、`story_plan` 章纲、`story_write` 正文、`story_review` 审稿、`story_revise` 修订、`story_state` 状态结算、`story_status` 只读进度。
- 正文首版是 `chapters/ch-<四位序号>.md`；修订生成 `ch-<序号>.r2.md` 这类新版本，旧版不改写。
- 章节末尾不写“作者的话”，不写总结段落。

## 写作纪律

- 人物做什么必须能被其目标与处境解释；解释不了就改行为，而不是补一段心理独白。
- 每章至少一个具体可感的细节（物件、动作、对话里的口气），不要只写情绪判断。
- 不用“他知道，这一切都变了”这类总结句代替事件。
- 对话承担信息与立场冲突；连续三段以上纯对话没有动作或环境，就要重写。
- 时间线、称谓、地名、能力边界与既有设定冲突时，以设定为准，改新写的部分。

## 自检清单

- 本章目标是否在结尾发生了变化？没有变化就不是一章。
- 有没有一段可以整段删掉而不影响后文？有就删。
- 人物台词去掉名字后，还能分辨出是谁在说吗？
- 新出现的事实是否与既有设定冲突？冲突是否已在正文里被处理？
- 结尾是否给出下一步的具体期待（而不是“暴风雨即将来临”这种空话）？

## 脚本

`scripts/chapter-status.mjs` 扫描作品目录，列出已有章节、每章字数与偏短章节。开工前跑一次，能立刻看出进度与缺口。

```bash
node <技能目录>/scripts/chapter-status.mjs <作品目录>
```
