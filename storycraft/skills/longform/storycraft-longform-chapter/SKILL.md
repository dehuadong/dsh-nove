# 长篇小说单章写法

形态：`story_init` 的 `form: "longform"`（省略即此值）。章节单位是「章」。

一个章节只追求一件事：让读者在读完后有明确的“接下来会怎样”的期待，同时不破坏已经建立的人物与事实。

## 开工前必须先读

1. 先调 `story_brief`：它按预算装配好作者意图、本章章纲、涉及人物、未解伏笔、本卷摘要、最近 5 章摘要、上一章结尾、文风与字数口径。**不要自己通读前文**，也不要凭记忆推断设定。
2. 章纲缺失、真值缺文件、目标章不存在时，`story_brief` 会明确报错——按错误里的提示补，不要编造。
3. 需要更具体的设定时，用 `story_bible` 读五件真值（世界观、人物、文风、计划、意图），不要用文件工具去翻 `works/`。

## 先讨论，后立项

作者用自然语言提想法时，**先讨论**：前提、主要人物、核心冲突、想写的体验，优先复用作者已经说过的内容。讨论阶段不写任何文件，也不调用 `story_init`。

方向成熟后，用 `story_propose` 落一份建项方案（标题、形态、一句话前提、主要人物、冲突、约定），把方案讲给作者看，**等作者明确同意**后再 `story_init`（带 `proposal`）。立项完停下，等作者决定要不要写第一章。

立项后还有一层：**全书计划**。用 `story_outline` 写主线、卷划分与结局方向（落 `bible/plan.md`），讲给作者看；作者确认后用 `story_outline(approve: true)` 记录。未确认前 `story_plan` 会被拒绝（`outline-required`）——重写计划会清掉确认，需要重新确认。

## 写作流程

0. **先问下一步**：调 `story_next`，它给出该做的动作、章号、原因与缺什么。顺序固定为：章纲 → 正文 → 审稿 → 修订 → 定稿 → 摘要 → 下一章章纲。动作被拒时，错误消息里的「先做什么」就是下一步。

1. **定章纲**：视角人物、本章目标、阻力、代价、结尾变化，五项齐全后用 `story_plan` 落盘。用户没给章纲时，先给章纲让用户确认。
2. **取上下文**：调 `story_brief`，按返回的分段写，不要引用被裁掉的段。
3. **写成稿**：二到四个场景，场景之间有时空或因果推进；正文用 `story_write` 落盘。首版 `ch-<四位序号>.md`，修订生成 `r2`、`r3` 新版本。
4. **质检**：用 `story_critique` 看可复现指标（字数是否在该作品范围内、平均句长、重复句、AI 腔命中、对话占比）。它只打分，不改正文。
5. **审稿**：把质检发现与自己的问题写成清单交给 `story_review`（只落盘清单，不动正文）。
6. **修订**：用 `story_revise` 按条目标记为已处理并生成新版本。选模式：
   - `patch`（默认）只改点到的地方，字数变化 ≤ 20%；
   - `polish` 顺语气与节奏，≤ 40%；
   - `rewrite` 重写，不限幅度；
   - `deslop` 专治腔调词，必须减少命中（原文零命中时可用）。
   模式与幅度不符会被拒绝，按错误提示换模式。
7. **定稿**：`story_next` 说可以定稿、且阶段是「已修订」时，用 `story_state` 写本章的人物事实与伏笔变化（只写变化，不重抄设定）。
8. **摘要**：定稿后用 `story_summarize` 给本章写摘要（上限 400 字，只写事实与状态变化）。下一章的滚动窗口靠它。

## 卷

一卷是若干章的连续区间，按故事线由作者确认，不固定章数：

- 模型按情节给出建议（例如 40–50 章一卷），作者同意后用 `story_volume` 落盘（标题、起止章、可选卷摘要）；
- 区间不得与其它卷重叠，章必须已存在；
- 卷摘要会进下一卷各章的写前上下文；卷内最后一章定稿后，提醒作者补卷摘要。

## 已定稿的章要改

- 只补审稿或改稿、正文不动：先 `story_reopen`（只作废定稿、不改正文），再走 审稿 → 修订 → 定稿。
- 要连正文一起重写：`story_write` 带 `reopen: true`，生成新版本，同样重走三步。

## 设定与参数

- 字数范围按作品设定：建档时用 `story_init` 的 `wordRange` 与作者商定；老作品用 `story_settings` 改或清空。未设定就不按字数判定。
- 作品改名/删除/恢复：`story_rename`、`story_delete`（进回收站）、`story_restore`。

## 输出契约

- 正文、章纲、审稿清单、摘要、状态、卷一律由动作落盘，不要用文件工具直接写 `works/`：动作负责版本、进度清单、暂存与提交，直写会让进度与文件不一致。
- 只读动作：`story_next`、`story_brief`、`story_bible`、`story_critique`、`story_status`、`story_volumes`。
- 章节末尾不写“作者的话”，不写总结段落。

## 写作纪律

- 人物做什么必须能被其目标与处境解释；解释不了就改行为，而不是补一段心理独白。
- 每章至少一个具体可感的细节（物件、动作、对话里的口气），不要只写情绪判断。
- 不用“他知道，这一切都变了”这类总结句代替事件。
- 对话承担信息与立场冲突；连续三段以上纯对话没有动作或环境，就要重写。
- 时间线、称谓、地名、能力边界与既有设定冲突时，以设定为准，改新写的部分。

## 自检清单

- 本章目标是否在结尾发生了变化？没有变化就不是一章。
- 有没有一段可以整段删掉而不影响后文？有就删。
- 人物台词去掉名字后，还能分辨出是谁在说吗？
- 新出现的事实是否与既有设定冲突？冲突是否已在正文里被处理？
- 结尾是否给出下一步的具体期待（而不是“暴风雨即将来临”这种空话）？

## 脚本

`scripts/chapter-status.mjs` 扫描作品目录，列出已有章节、每章字数与偏短章节。开工前跑一次，能立刻看出进度与缺口。

```bash
node <技能目录>/scripts/chapter-status.mjs <作品目录>
```
