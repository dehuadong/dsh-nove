# Proposal

已配置的工作跟踪器或既有工作项是本次规划的根工作项，负责为什么要改、本次范围、产品行为与验收、评审与批准证据及就绪状态，并链接长期技术设计的属主。没有跟踪器时，当前任务会话承担这些职责。

## 配置与存放

使用项目已配置的工作跟踪器（如有）；跟踪器配置是可选的。没有跟踪器时直接在当前任务中维护本次规划，不要求创建 Issue 或单独的 Proposal 文件。复用合适的既有工作项；一个工作只保留一个规划根节点，不同时创建远端 Issue 与重复的本地 Proposal。

## 内容

遵循项目既有格式。项目没有格式时使用 [proposal-template.md](./proposal-template.md)。内容与工作规模相称：

- **目标与选定范围**：为什么做、本次交付哪一段以及重要排除项；
- **产品合同**：写清本次产品行为与验收；跨工作项持续生效的合同引用已登记的独立 Spec，并明确本次适用部分；
- **决定**：本次范围或产品选择、未解决问题、Plan Review 与批准证据；长期技术选择的正文留在选定的设计属主；
- **引用**：相关 PRD、独立 Spec、Agent Note，以及实施工作项。从工作项链接到 Note；Note 不为追踪工作进度反向链接工作项。没有远端或本地跟踪器时，当前任务会话就是工作项，不另外创建重复记录。

Proposal 不复制独立 Spec 或设计正文。存在独立 Spec 时，Proposal 明确本次选取的修订与范围；技术方案、备选与长期理由由选定的设计属主完整说明。

## 状态更新

使用项目配置的工作状态与证据约定；没有跟踪器时，在当前任务记录 Plan Review 结果、批准和就绪状态。只有规划内容通过、所需批准齐备且没有阻塞时，才标记为就绪。

评审通过、批准和执行授权是三件不同的事。

详细产品合同、技术设计和实施进度分别留在自己的属主中。
